# Алгоритмический мини-пакет

## Запуск

`pip install -r requirements.txt`

`python -m lab4` — демонстрация работы

`python -m pytest` — тесты

## Рекуррентная задача — быстрая степень

Степень вычисляется за O(log n): показатель делится пополам, при чётной
степени основание возводится в квадрат, при нечётной — домножается к
результату. Реализованы итеративная (`pow_it`) и рекурсивная (`pow_rec`)
версии. При отрицательном показателе вызывается `InputError`.

Ограничение рекурсии: Python ограничивает глубину рекурсии примерно
1000 кадров (`sys.getrecursionlimit()`), поэтому `pow_rec` может упасть
с RecursionError на очень больших показателях, `pow_it` — нет.

Поведение при неверном типе: основание и показатель должны быть числами,
иначе вызывается `InputError` (или `TypeError` от Python).

## Сортировки

- Selection Sort: время O(n^2), память O(n) из-за создания копии.
  Вход не изменяется. Сортировка нестабильна.
- Heap Sort: время O(n log n) в худшем и среднем случае, память O(n)
  из-за копии. Сложность не зависит от исходного порядка, поэтому
  на обратном входе деградации нет.

Поведение при неверном типе: сортировки работают со сравнимыми
элементами (числа, строки); при несравнимых элементах Python
вызывает `TypeError`.

## Структура данных — приоритетная очередь

Реализована на бинарной куче (min-heap).

- `push` — добавление, O(log n)
- `pop` — извлечение минимума, O(log n)
- `peek` — просмотр минимума, O(1)
- `len(q)` и `bool(q)` поддерживаются

Дополнительная память — O(n). При `pop`/`peek` над пустой очередью
вызывается `EmptyError`.

## Генераторы наборов

`gen_random`, `gen_sorted`, `gen_reverse`, `gen_near` (почти
отсортированный), `gen_dup` (много дубликатов). Поддерживают `seed`
для воспроизводимости.

## Бенчмарк

Для замеров используется `time.perf_counter()`, 5 повторов, берётся
среднее. Замеряются сортировки, генерация входа в замер не входит,
для каждого запуска создаётся независимая копия входа. Размеры:
100 000, 1 000 000, 10 000 000.

Selection Sort замеряется до 100 000: при O(n^2) на больших размерах
время непомерно, поэтому в выводе этих ячеек нет. Heap Sort замеряется
на всех размерах.

Результаты замеров воспроизводятся командой `python -m lab4` и
зависят от машины — это нормальное свойство любых bench-замеров.

Интерпретация ожидаемых результатов: время selection растёт квадратично —
при умножении n на 10 время растёт примерно в 100 раз, поэтому на
1 000 000 элементов ему понадобились бы часы. Heap Sort растёт как
O(n log n) — при умножении n на 10 время растёт примерно в 10–13 раз.
На обратном и почти отсортированном входах деградации нет: сложность
heapsort не зависит от исходного порядка данных.
